# Все 10 туннелей: локальный Linux TUN, шесть профилей
Два Linux amd64 бинарника из текущего рабочего дерева, включая незакоммиченные изменения; ревизия, окружение и SHA-256 в `harness/build-environment.txt`. Один туннель и один профиль за раз. Маршрут 10.77.0.2 → btawg0 → реальный транспорт → btawg0 → 10.77.0.1; без SOCKS-прокси, балансера, DHT-поиска или внешнего Интернета. Для каждой ячейки новый хаб, БД, экспорт v2 и клиент; соединение поднято до включения профиля. Задержка указана в одну сторону; netem на обеих сторонах транзитного netns. Потери независимые по направлениям (разные фиксированные seed); без ограничения полосы. На четырёх veth отключены TSO/GSO/GRO и UDP segmentation/coalescing во всех профилях; TUN MTU 1280. С другими настройками offload/нагрузки напрямую не сравнивать.

Полезный TCP у приёмника (дельты TCP_INFO.bytes_received, CUBIC). В каждой ячейке: download 1 → 8 потоков, затем upload 1 → 8 потоков. На направление: 1 с прогрева + 2 с P1, затем 0.75 с прогрева + 3.25 с P8. Первый поток продолжается в фазе P8. Затем две последовательные фазы UDP по 2 с с приёмом опоздавших пакетов ещё 400 мс, payload 1152 байта с номером. Цель UDP = 110% от P8 того же направления; фактическая нагрузка, число уникальных ответов и джиттер в udp.tsv. Неполучено = потеря **или опоздание** после этого окна. Относительная нагрузка не равна абсолютной ёмкости UDP. Ниже ↓ / ↑ — приём / передача с точки зрения клиента.

При TCP P8 = 0 вместо нулевой отправки использовался один диагностический UDP-пакет. Процент на единичных пакетах не оценивает вероятность потерь; абсолютные числа `sent` и `received` приведены в udp.tsv. Ноль TCP означает именно ноль новых байтов у приёмника в измерительном окне, не отказ установить соединение.

Для воспроизведения с теми же бинарниками распаковать `raw.tar.gz` и выполнить `bash harness/replay.sh /каталог/с/замеренными/бинарниками` на Linux с TUN, user/net namespaces и CPU 0–7. Проверяются SHA-256 `btawg-client` и `btawg-server`.

Счётчики очередей и CPU даны за всю ячейку (с подключением сокетов), не за отдельную TCP-фазу. CPU: 100% = одно логическое ядро; affinity хаба 0–3, клиента 4–5, нагрузки 6–7. Зонд ICMP 20 Гц одновременно с нагрузкой. P95 рассчитан только по полученным ответам, доля без ответа учитывает и незавершённые эхо на границе окна. По одному короткому прогону на ячейку, без доверительных интервалов; это не длительная установившаяся скорость. TCP retrans — повторно переданные сегменты, не процент потери.
